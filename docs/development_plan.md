# 单视图测高开发顺序与验收标准

**已确认的验收主线**是受控场景下的全自动测高。布置好标记并登记一次参考高度后，每张照片无需手动点选，程序自动识别地面方向、参考物和目标端点，输出高度、解释图、质量状态和实验记录。无标记照片可用手工或半自动模式。三种模式共享几何核心和结果格式，开发按依赖顺序推进。

以项目目标、数据协议和验收标准决定实现。初始代码可按需要替换模块或重做主流程。接口变更同步到 README，并通过相应的复现与验收用例。

**Pre 是 12 月 10 日的项目介绍。** 一名成员在五分钟内用一个例子讲清任务、方法、预期输出、对照实验和分工。这份开发顺序不为 Pre 设置实现门槛。写好的真实结果标明来源，示意数字标明是示例。[Pre 内容提纲](oral_presentation.md)

## 1 固定测量协议与数据

- [ ] 采用[场景格式](../data/README.md)。锁定参考物 ID、原图坐标、米制输入及人工线组 `h1/h2/v`。自动模式使用 `rig.json` 保存编码与角色，参考高度来自 `reference.txt`。目标真值存到 `truth.txt`，由评价程序单独读取。所有模式输出同格式的标注与运行记录。
- [ ] 整理三类数据。用独立投影器生成已知俯仰、参照和目标高度的合成图。公开图用于核对几何和无标记模式，记录版本、出处和尺寸。保留少量自采标记场景作独立验收。[公开样例见牛津论文图 21](https://www.robots.ox.ac.uk/~vgg/publications/2000/Criminisi00a/criminisi00a.pdf)
- [ ] 统一布置与拍法。共同支撑平面布置四个矩形角标，竖直物体端点布置角色标记。三脚架固定机位，记录俯仰、侧倾、镜头和场景。两人核对标记角点与实际顶脚，避免把标记安装偏差归到测高公式。验收照片留到参数固定后再跑。

**验收**是至少一份可公开的合成样例含完整标注和独立真值。两人能按同一份说明得到一致的输入，测量入口无法把目标真值当作输入尺度。

## 2 实现和验证统一几何

- [ ] 在 `src/metrology.py` 实现齐次几何、方向组的消失点、地面消失线、参考尺度转移与高度估计。保留 `w=0` 的合法表示，由一套几何覆盖水平、仰俯和近似同深度。人工线优先用两线求交建立基线，再实现正规化后的多线拟合。
- [ ] 对非法参考高度、重复点、重合方向、接近消失线的底点、病态分母和明显违反竖直假设的标注，给出具体失败原因。焦距是独立诊断，适用于符合假设的有限消失点组合。无法计算时标记 `not_applicable`，高度流程仍按自身条件判断。
- [ ] 用 `tests/test_metrology.py` 核验水平 1.50 m、倾斜 1.50 m、传高方向在无穷远、同深度、齐次向量尺度不变、错误输入显式失败。可用独立针孔投影补充一般情形。数值用例的建议绝对误差不超过 `1e-6 m`。

**验收**是理想用例通过，非法用例返回明确失败结果。1.50 m 是合成真值，真实照片精度由后续验收数据决定。[测高原理与交比](https://visionbook.mit.edu/3d_scene_understanding_single_view.html#measuring-the-height-of-an-object)

## 3 跑通人工线和结果导出

- [ ] 提供可复跑的命令行入口。以 `python -m src.metrology` 作为建议起点，接口定稿后用实测命令更新 README。人工模式读已标好的线和物体端点，默认用于可复跑示例。
- [ ] 生成 `overlay.png`、`heights.csv`、`run.json`。图中标出参考、目标、消失线与传高路径。位于无穷远的消失点用方向箭头表示。CSV 逐目标存 ID、估计、可选真值与误差、状态和原因。`run.json` 记录图像版本、标注、线源、参数、软件版本与随机种子。真值缺失时保留测量，误差列留空。
- [ ] 另一成员在独立环境按 README 命令复跑合成样例并核对高度与状态。再用一个符合几何假设的公开照片走完整个流程。

**验收**是从干净环境用一条命令生成同样的数值、状态和解释图，复放时无须重做人工标注。

## 4 跑通标记场景的全自动模式

- [ ] 用 OpenCV ArUco 自动检测 ID 与四角。按 `rig.json` 取出四个平面标记及参照和目标的顶脚标记。对平面标记取对角线交点得到投影中心，用矩形两组对边恢复消失线。顶脚采用协议指定的标记角点及印刷方向，验证旋转图像中的角色映射。[OpenCV ArUco 检测器](https://docs.opencv.org/4.12.0/d2/d1a/classcv_1_1aruco_1_1ArucoDetector.html)
- [ ] 由两根不同投影轴恢复竖直消失点，齐次形式保留无穷远。受控拍摄中若竖直投影轴几乎重合、点位不稳或支撑不足，返回复核或失败。可引入第三条独立的竖直边交叉检查。恰好两条投影轴确定一个解时，仍记录它们缺少额外几何支持。
- [ ] 接通 `--mode auto`。测量阶段只读取照片、角色配置和已知参考高度，估计器不读 `truth.txt`、目标物理高度、标记物理边长或标记姿态尺度。导出检测角点、派生标注和运行记录，让同一几何输入可以用人工入口重放。
- [ ] 测试完整标记、旋转、水平、轻微仰俯以及遮挡。缺标、重复 ID、平面四边形自交或几何退化时给出可识别的失败原因。矩形和共同支撑平面由采集时核对。检测失败不自动造点。复核和失败状态均可切换到人工处理，且不算作零点击成功。

**验收**是支持范围内的新照片只加载图像和已保存配置即可自动出高度。拿掉所需标记后能正确报失败，并保留可追踪的状态和原因。

## 5 加入无标记照片的半自动入口

- [ ] 用 OpenCV 提取线段候选，按长度和相邻位置去除明显杂线、优先合并同一物理边的碎段。让用户确认或更正 `h1/h2/v`，支持删除错线和补线。物体顶脚和参考高度继续由人确认。[OpenCV 线段检测](https://docs.opencv.org/4.10.0/db/d73/classcv_1_1LineSegmentDetector.html)
- [ ] 用 RANSAC 筛除离群线，用支持线重估每组消失点。推荐在段中点用线段方向与指向消失点的方向之间的无向夹角作为残差，有限和无穷远方向共用同一计算。记录每组独立物理边数量、内点数与残差。只有两条独立线时可出几何候选，但将缺少冗余作为复核理由。
- [ ] 对线分组错误、线段过短或支持过少给出可操作提示，让用户重选或退回手工模式。参数和随机种子可重放。

**验收**是同一照片能走人工与半自动两路，两路共用物体端点和参考高度。半自动候选需要更正时，能指出是哪组线有问题，并保留更正记录。

## 6 做误差诊断和独立实验

- [ ] 对同一批标记图比较直接像素高度比、人工标注几何与全自动几何。端到端对照允许人工和自动端点各自产生，并单独固定一套端点比较消失线和竖直估计的影响。无标记图的人工和半自动结果单列。记录绝对误差（厘米）、相对误差、分组 MAE、零点击成功率和失败原因。分开报告准确度和人工操作成本。
- [ ] 两人独立重复标注少量同图。对线段与物体端点做 1、2、4 像素扰动，在固定随机种子下重算整套流程。把结果称为「标注扰动区间」，报告无效运行数量。遇到较宽的区间，提示用户复核对应线组或端点。
- [ ] 由几何一致性、独立线组支持和扰动稳定性产出三级质量状态。**可报告**时显示高度与解释图，**需复核**时显示具体原因和建议动作，**无法可靠测量**时记录失败原因并留空高度。阈值只用开发数据选择，随后在保留的自采图上统一运行。
- [ ] 自采可从两个目标、三种前后位置做起，补少量轻微倾斜和遮挡样例。说明哪些图共享场地或物体，按条件汇总并保留所有失败。组内可将合格布景留出集的零点击成功率至少 90%、成功案例相对误差中位数不高于 5% 作为建议目标。按开发试拍确认并冻结目标和纳入条件后，再看留出集结果。这两个数是内部目标，课程文件没有规定这类指标。

**验收**是同一份脚本可重生成表和图。证据能回答「透视校正改善多少」「有多少照片实现零点击」「何种输入会导致失败」。

## 7 完成离线演示与课程交付

- [ ] 一页离线演示串起加载配置、选图、自动测量和查看结果。失败后可以进人工复核，提供放大、重选、撤销、保存和复放。用颜色与文字同时标出三个方向及质量状态。准备一张无需点标记的成功图和一张因缺标等条件而拒测的失败图。
- [ ] README 提供验证过的依赖组合、样例和复现命令。保留软件要求、预训练模型和测试准备栏目。关键代码写清公式假设与失败条件。附上能分享的场景样例、实验表和图，保留原始来源记录。
- [ ] 完成英文模板 PDF，摘要末行写团队 GitHub URL。包含两人贡献、正文引用、定量实验和失败分析。提交文件用中文命名，包含两人姓名及学号，一名成员负责上传。[报告结构](report_map.md)

**验收**是另一成员能在自己的环境复放成功和失败案例，重生成关键图表，并逐项核对 README 与报告中的结果。

## 两人协作

| 角色 | 可并行的任务 | 汇合点 |
| --- | --- | --- |
| 几何与工具 | 齐次计算、消失点估计、标记角色映射、质量状态、交互演示 | 用第一阶段的数据协议接入测量 CLI |

两人一起确认方案和署名，把自己负责的成果交给另一位复跑。计划中的功能和档案均以实际验收结果更新。
